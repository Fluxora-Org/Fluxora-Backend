# Fluxora API Changelog

This changelog is the single record of **externally visible** changes to the Fluxora HTTP API.
It is grouped by API version — the versions negotiated through the `Accept-Version` header and
enforced by [`src/middleware/apiVersion.ts`](../../src/middleware/apiVersion.ts). Deprecations are
announced here before they are enforced by [`src/config/deprecations.ts`](../../src/config/deprecations.ts).

## Scope

Each entry names one API **scope** and describes what changed for consumers:

- `` `GET /api/streams` `` — a single endpoint (HTTP method + path, exactly as it appears in
  [`openapi.yaml`](../../openapi.yaml)).
- `` `ALL /api/rate-limits/config` `` — a route-wide deprecation or the end of that deprecation,
  covering every method on the path.
- `` `*` `` — a cross-cutting behaviour that is visible on every request or response (for example
  version negotiation headers), not tied to a single endpoint.

Breaking changes carry the distinct `[breaking]` marker so they can be found at a glance.

## How to update this file

New versions are added at the **top**, newest first. Within a version, group entries under the
`### Added`, `### Changed`, `### Fixed`, `### Deprecated`, and `### Removed` headings. Add one entry
per scope. `### Removed` entries must carry the `[breaking]` marker; any `### Changed` or
`### Fixed` entry that forces a consumer to change their code must carry it too.

After updating this file and `openapi.yaml`, refresh and verify the released-contract snapshot:

```bash
pnpm run update:api-changelog
pnpm run check:api-changelog
```

`docs/api/releases.json` is generated by the update command and records the OpenAPI contract,
registered deprecations, and fingerprints for each released head version. Do not edit it by hand.
Commit it with the changelog and OpenAPI changes so the next change is compared with the previously
released contract.

`scripts/check-api-changelog.mjs` validates these files in CI. It enforces that:

1. Every API version served by `SUPPORTED_VERSIONS` has a section here, and the newest section is
   currently served.
2. Every scope that exists in `openapi.yaml` is recorded as live in the changelog, and every scope
   recorded as live exists in `openapi.yaml`. Adding or removing an endpoint without a changelog
   entry therefore fails the check.
3. Every route registered in `src/config/deprecations.ts` has a matching `### Deprecated` entry
   (including its `YYYY-MM-DD` sunset date), and every deprecation announced in the newest section is
   registered.
4. Every operation, shared contract, and deprecation-state change since the released snapshot has
   a matching entry. New or moved deprecations use `ALL /path` under `### Deprecated`; ending one
   uses the same scope under `### Changed` or `### Fixed`. Breaking changes must carry `[breaking]`;
   documentation-only changes must not.
5. `### Removed` entries always carry `[breaking]`, while `### Added` and `### Deprecated` entries
   never do.

To fix a failure, record the change for the affected version and update `openapi.yaml` where the
surface itself changed. Never edit the check or release snapshot to silence it.

## v1

The initial stable API version. `Accept-Version: v1` is the only supported version and the default
when the header is omitted; every accepted response echoes the resolved version in `X-API-Version`.

### Added

- `*` — Requests may select the API contract with the `Accept-Version` header (`v1`, `1`, or `1.0`
  all resolve to `v1`; the header is case-insensitive). Requests for any unsupported version are
  refused with `400 unsupported_version` and a list of supported versions. Every accepted response
  echoes the resolved version in the `X-API-Version` response header.
- `GET /` — Service metadata (`name`, `version`, `docs`).
- `GET /health` — Liveness and dependency health status; returns `503` while the service is shutting
  down.
- `GET /health/ready` — Readiness probe; returns `200` when all dependencies are healthy or degraded
  and `503` when a dependency is unhealthy.
- `GET /health/live` — Detailed health report for all dependencies.
- `GET /api/admin/status/read-only` — Public pause-flag status; readable without authentication.
- `POST /api/auth/session` — Issues a signed session token for a Stellar address and role.
- `GET /api/streams` — Cursor-paginated stream listing with `limit`, `cursor`, `status`, `sender`,
  `recipient`, and `include_total` query parameters.
- `POST /api/streams` — Creates a streaming payment; requires a unique `Idempotency-Key` request
  header.
- `GET /api/streams/{streamId}` — Returns a single stream record; supports conditional GET through
  `If-None-Match` (matching `ETag` yields `304 Not Modified`).
- `GET /api/streams/{streamId}/poll` — Long-poll fallback for stream updates; accepts a `since`
  cursor to replay missed events.
- `DELETE /api/streams/{streamId}/poll` — Abandons an in-flight long-poll connection.
- `POST /internal/indexer/sync` — Triggers an indexer sync for a ledger sequence.
- `POST /internal/indexer/events/replay` — Starts historical contract-event replay.
- `GET /internal/indexer/events/replay` — Reports current replay progress and status.
- `GET /internal/indexer/status` — Reports indexer status and state.

### Deprecated

- `ALL /api/rate-limits/config` — The active rate-limit configuration endpoint is scheduled for removal on **2026-09-30** (sunset date `2026-09-30T00:00:00.000Z`); use deployment-managed rate-limit configuration and call `GET /api/rate-limits` for caller status. See [the deprecation policy](./deprecation-policy.md) for the consumer guide; responses carry `Deprecation: true`, `Sunset`, and `Link` headers until removal.
