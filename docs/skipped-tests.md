# Skipped-test inventory

This inventory addresses [issue #1248](https://github.com/Fluxora-Org/Fluxora-Backend/issues/1248). It is an explicit audit of every skipped test that existed when the issue was assigned. The initial count was 42. Two obsolete placeholder suites were deleted, the filesystem failure regression was enabled, and the remaining 39 skips are intentional environment gates.

## Classification policy

| Classification   | Meaning                                                                                                                                                            | Standard command |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |
| Enabled          | The test can run in the standard unit-test environment and must not be skipped.                                                                                    | `pnpm test`      |
| Delete           | The test targets a removed implementation and has no executable assertion to preserve. Its replacement coverage is linked below.                                   | N/A              |
| Keep-gated       | The test needs an external service or fault-injection stack that standard CI does not provide. A skip is retained, but the reason and opt-in command are recorded. | See inventory    |
| Excluded live-DB | The issue explicitly excludes these five suites. They retain their existing `DATABASE_URL` gate and remain separately tracked as live PostgreSQL coverage.         | See inventory    |

The policy deliberately does not turn every environment-dependent suite into a fake unit test. That would make the test count look healthy while removing the network, database, and recovery guarantees these suites were written to verify. The test suite reports these tests as skipped, not passed, and this file records the required environment and command for each one.

## Prevention

The remaining skip sites must keep a nearby comment naming the external prerequisite and linking to #1248. A blanket “no skips” lint rule is not appropriate here: it would either reject valid chaos/live-service gates or encourage developers to replace real integration coverage with mocks. During review, new skips should be added only with the same classification, an opt-in command, and a tracking issue; this inventory should be updated whenever the count or classification changes.
